Retail Sales SQL Analysis & Business Intelligence

A comprehensive exploratory data analysis (EDA) and business intelligence case study built on relational Point-of-Sale (POS) retail data. This project transforms raw transactional logs into actionable merchandising, staffing, and customer retention strategies using MySQL DDL/DML, Common Table Expressions (CTEs), and Window Functions.

Project Specification
Database Name reatail_sales_project_analysis
Fact Table retail_sales (11 cols)
Product Categories Electronics, Clothing, Beauty
Currency Unit INR (₹)
Analytical Scope 10 Core BI Questions
1. Business Problem

Retail leadership lacked granular visibility into which product categories drive top-line revenue, how customer demographics (age & gender) vary across departments, when peak store shifts occur, and who the highest-spending VIP shoppers are.

2. Analytical Objectives
  • Architect a typed relational table (retail_sales) with primary key integrity.
  • Quantify category revenue, high-value orders (>₹1,000), and unique reach.
  • Identify seasonal revenue peaks per year & Top 5 VIP customers.
  • Segment order volume across Morning, Afternoon, and Evening shifts.
3. Methodology & Validation

Followed a 4-stage SQL workflow: (1) Database & DDL Creation, (2) Record Verification (COUNT(*) & sample inspection), (3) Multi-Dimensional EDA using CTEs & Window Functions, and (4) Code Quality Audit to resolve schema and grouping edge cases.

          Code Quality & Engineering Rigor
          
SQL Code Audit & Production Refinements

          
Four subtle syntax, grouping, and naming issues identified during code review—with side-by-side before & after fixes for production deployment.

        

        
      


      

        
        

          

            

              DDL SYNTAX FIX #1
              
DECIMAL Precision Syntax (10.2 vs 10,2)

            

          

          

            In CREATE TABLE retail_sales, decimal(10.2) uses a dot instead of a comma, which triggers a SQL syntax error in strict MySQL/PostgreSQL engines.
          

          

            

              
Before (Original)

              price_per_unit decimal(10.2),

              total_sale decimal(10.2)
            

            

              
After (Production Fix)

              price_per_unit DECIMAL(10, 2),

              total_sale DECIMAL(10, 2)
            

          

        


        
        

          

            

              SQL GROUPING FIX #2
              
Missing GROUP BY category on Distinct Count

            

          

          

            Selecting a non-aggregated column (category) alongside COUNT(DISTINCT customer_id) without GROUP BY category fails under ONLY_FULL_GROUP_BY mode.
          

          

            

              
Before (Original)

              SELECT category, COUNT(DISTINCT customer_id) AS customers

              FROM retail_sales;
            

            

              
After (Production Fix)

              SELECT category, COUNT(DISTINCT customer_id) AS customers

              FROM retail_sales GROUP BY category;
            

          

        


        
        

          

            

              SCHEMA NAMING #3
              
Column Identifier Typo (quantiy → quantity)

            

          

          

            Consistent spelling in DDL prevents downstream BI tool confusion. While the query consistently references quantiy, standardizing to quantity improves maintainability.
          

          

            

              
Before (Original)

              quantiy INT ... WHERE quantiy >= 4
            

            

              
After (Production Fix)

              quantity INT ... WHERE quantity >= 4
            

          

        


        
        

          

            

              LABEL CLEANUP #4
              
Shift Label String Typo ('agternoon' → 'Afternoon')

            

          

          

            In the operational shift CASE statement, 'agternoon' had a typo and inconsistent title casing compared to 'morning' and 'evening'.
          

          

            

              
Before (Original)

              WHEN HOUR(sale_time) < 17 THEN 'agternoon'
            

            

              
After (Production Fix)

              WHEN HOUR(sale_time) < 17 THEN 'Afternoon'
